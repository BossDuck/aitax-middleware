Flujos de Procesamiento
🧾 Ruta A — Facturas (invoice / finished)
1
API externa dispara extraction.created o extraction.updated
2
router.py valida HMAC, guarda en webhook_events, encola tarea
3
Worker lee evento · GET /extractions/{id} a API externa (estado real)
4
event_router.py confirma extractor=invoice, status=finished
5
Busca Company por RFC en DB → si no existe: FAILED
6
POST /sync/sync-started/ → Django: ExtractionSyncStatus = SYNCING
7
sync_all(company): ThreadPoolExecutor, facturas por año, conceptos y pagos
8
rebind_orphan_fks() repara FKs nulas por orden no determinista del parallelismo
9
POST /sync/extraction-completed/ → Django actualiza status, envía email
10
Evento marcado PROCESSED en DB
📄 Ruta B — Tax Docs (tax_status / tax_compliance)
1
Mismo flujo de recepción, validación y encolado
2
event_router.py detecta extractor ∈ {tax_status, tax_compliance}
3
Solo actúa si status ∈ {finished, error, stopped}. Si no → SKIPPED
4
POST /sync/extraction-status-update/ con {extraction_id, extractor, status, rfc}
5
Django actualiza campo de status del contribuyente en su propia DB
6
Evento marcado PROCESSED
⚠️ Casos de error
→
HMAC inválido: 401 inmediato, evento no se guarda
→
JSON inválido: 400 inmediato
→
ClientDisconnect: WARNING, responde 200, proveedor reenvía
→
Company RFC no existe: FAILED permanente
→
API externa 5xx / timeout: Celery reintenta ×3 (60s→240s)
🔁 Idempotencia (2 capas) + Reintentos
①
Capa 1 — Endpoint HTTP: provider_event_id UNIQUE — duplicados rechazados en INSERT, log + 200 OK
②
Capa 2 — Worker: query por extraction_id ya procesado → SKIPPED con reason: extraction_already_processed
🔄 Reintentos Celery
↺
max_retries=3 · backoff exponencial: 60s → 120s → 240s · tope 10min
↺
Tenacity interno en clientes HTTP: 3 reintentos (2s→30s) — independientes de Celery
↺
Si Celery agota reintentos → MaxRetriesExceededError → evento marcado FAILED
🔗 Upsert Strategy
↑
pg_insert().on_conflict_do_update(index_elements=['provider_id'])
↑
created_at excluido del UPDATE (Django auto_now_add=True — se setea solo en INSERT)
↑
_trunc(val, max_len) trunca strings a los VARCHAR limits de Django
